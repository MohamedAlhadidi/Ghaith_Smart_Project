# عالم غيث التعليمي — مراجعة تقنية وتربوية V4 (الحزمة المصححة)

هذه حزمة **تعليمات إدارة ومشغّل**، وليست منصة تعليمية مطورة؛ لا يوجد فيها محتوى معتمد للمناهج أو ألعاب قابلة للتشغيل بعد.

## أهم إصلاحات V4
1. السماح بوجود `Bash` عبر `--tools` تحت وضع `auto`، دون تفعيل تجاوز الموافقات، لتصبح عمليات البناء والاختبار ممكنة من حيث المبدأ.
2. طلب تشغيل Bash داخل sandbox حقيقي (`bubblewrap` و`socat` على لينكس) مع `failIfUnavailable=true`. إذا تعذر العزل يتوقف التشغيل بدل الرجوع لوضع غير معزول.
3. فحص إصدار CLI وأعلامه قبل دورة الذكاء الاصطناعي، والحد الأدنى 2.1.314 بسبب حجب الكتابة خارج مجلدات العمل.
4. فهم حالات `ready`, `verified`, `needs_review` وتجنب تعليق التبعيات؛ تتطلب المراجعات البشرية وصول الإنسان.
5. التقدم يتحقق مبدئيًا من **إغلاق مهمة جديدة مع تغير ملف عمل**، لا من تعديل السجلات فقط. هذه إشارة تقدم تقنية وليست إثبات صحة تعليمية.
6. احتساب دورات التشغيل التي بدأت حتى لو انهارت قبل كتابة نتيجة، مع حد يومي محافظ يعتمد على سقف تكلفة الدورة لا التكلفة الفعلية وحدها.
7. تحديث معيار كثافة الألعاب: 10–14 جولة/نشاطًا مناسبًا عند توافر مادة كافية؛ التنوع عبر مستوى الوحدة والمهارات، مع منع حشو ست آليات صورية لكل درس.
8. ضرورة game_manifest مستقل يطابق الألعاب بالدرس والحالة والاختبار عند الفحص النهائي.

## المتطلبات
- لينكس مع Python 3.10+، مستخدم غير root، مستودع خاص معزول من دون بيانات المؤسسة أو أسرارها.
- Claude Code 2.1.314 أو أحدث متاح عبر `PATH` مع تسجيل دخول صالح.
- sandbox مع `bubblewrap`, `socat` والإعدادات `sandbox.enabled` و `sandbox.failIfUnavailable`.
- ملفات المناهج الرسمية المناسبة للسنة والطبعة المطلوبة، ومراجعة بشرية لاعتماد مصفوفة المناهج.
- React/.NET/SQL Server أو ما يكافئ المتطلبات التقنية عند بدء تنفيذ التطبيق؛ لا تفترض توفرها مسبقًا.

## تجربة أولى بدون استدعاء النموذج
```bash
unzip Ghaith_Smart_Project_Manager_v4_AUDITED.zip -d ~/projects/ghaith-learning
cd ~/projects/ghaith-learning
export PATH="$HOME/.local/bin:$PATH"
claude --version
claude auth status
python3 -m unittest discover -s tests -v
python3 scripts/check_release.py --root .
./scripts/start_manager.sh --dry-run
```
يجب أن يفشل فحص `check_release.py` قبل بناء المنتج؛ هذا صحيح ومقصود. `dry-run` لا يتصل بالنموذج، ولا يتحقق من قدرة sandbox الفعلية.

## تشغيل أول دورة بموارد محدودة
```bash
./scripts/start_manager.sh --once
```
**مهم:** هذا الاستدعاء يحتاج اتصالًا وصلاحيات وحصة لاختبار Claude Code الحقيقي. لم يحدث هذا الاختبار على جهازك حتى الآن. بعد مراجعة النتائج وتشخيص البيئة فقط يمكن تشغيل:
```bash
./scripts/start_manager.sh
```

## حدود الاستمرار
- 28 خطوة في الدورة، حتى 2 دولار **تقديري** للدورة، 8 دورات محجوزة يوميًا، سقف يومي محافظ 12 دولارًا محجوزًا. التكاليف الفعلية/الاشتراك قد تختلف.
- 3 دورات دون إغلاق مهمة جديدة وتغير artifact توقف لتفادي الاستنزاف، أو 5 إخفاقات متتالية.
- إذا انتهت الحصة أو احتاج الأمر مراجعة بشرية أو توفر كتب غير موجودة، يوقف الاستدعاءات المكلفة ويطلب التدخل؛ لا يعد التنفيذ اللامتناهي ممكنًا.
- STOP وPAUSE: أنشئ الملف `control/STOP` أو `control/PAUSE` داخل مجلد المشروع. امسحه قبل الاستئناف.
- systemd template يحتاج استبدال `__PROJECT_PATH__` وتثبيت المستخدم، ويعيد التشغيل فقط بعد إخفاق غير مُصنّف. **لا تفعّل الخدمة قبل اختبار `--once`**.

## حدود الاختبار
اختبارات Python المحلية تختبر المشغّل وشروطه فقط. لا تثبت إطلاقًا صحة محتوى الصف الثاني، أو عمل تطبيق React/.NET، أو اتصال SQL Server، أو جودة التعلم عند الطفل، أو فعالية الخدمة على جهازك.

تقرير المراجعة المطول: `reviews/V3_TO_V4_DEEP_AUDIT_AR.md`.
