# تقرير التدقيق المكثف — عالم غيث التعليمي V3 → V4

**تاريخ التدقيق:** 14 نوفمبر 2026. **نطاق التقرير:** حزمة إدارة الوكيل والتشغيل وبرومبتات المحتوى، وليس تطبيقًا تعليميًا منجزًا.

## الحكم التنفيذي
V3 كان غنيًا تربويًا لكنه غير آمن للاعتماد على الاستقلالية الكاملة. لا يوجد في الحزمة تطبيق يعمل أو محتوى رسمي معتمد. أُجريت مراجعة شيفرة فعلية للمشغّل `scripts/pm_runner.py` وفاحص الإصدار `scripts/check_release.py` وقائمة المهام والبرومبتات ومصفوفة المنهج والقواعد. جرى تدقيق الرايات في صفحة CLI الرسمية: https://code.claude.com/docs/en/cli-reference؛ الأذونات: https://code.claude.com/docs/en/permissions؛ العزل: https://code.claude.com/docs/en/sandboxing.

## مراجعة الألعاب والتعليم — القواعد الحاسمة

1. لن نحسب عدد **الصور، أو الأسئلة، أو الجولات، أو القوالب** باعتباره عدد أنواع الألعاب. آلية اللعب تختلف فقط إذا تغير نوع التفكير أو اللمس/البناء/الصوت/حل المشكلة.
2. الرياضيات والإنجليزية: هدف 10–14 **نشاطًا/جولة أصيلة** لكل درس مناسب، موزعة بين الاستكشاف والتطبيق الموجه والمستقل والاختبار والمراجعة؛ و6 آليات لعب عبر **الوحدة** إن سمح المحتوى، وليس إجبار كل درس على ست آليات.
3. لا تستخدم اسم كلمة أو صوت إنجليزي غير موجود في المصدر أو المهارات السابقة المعتمدة. لا تولد كلمات غير منطقية لتلبية العدد، ولا تستخدم أحكام النطق الآلية بوصفها تشخيصًا.
4. كل عملية رياضية مولدة تملك قيود أرقام وشروطًا مستقلة ومدقق إجابة حتمي، مع اختبار الحدود والمشتتات وبدائل الحل المقبولة.
5. إذا أظهر غيث ضعفًا في مهارة، يقدم النظام شرحًا مختلفًا وتدريبًا أقصر في المستوى المناسب، ثم مراجعة لاحقة؛ لا يعرض 14 نشاطًا دفعة واحدة.
6. ألعاب 3D للأهداف التي تستفيد منها؛ دون التلاعب بنصوص PDF الأصلية أو تحويل أي درس إلى لعبة بلا مرجع منهجي.

## نتائج محلية متحققة

- `python3 -m py_compile scripts/pm_runner.py scripts/check_release.py`: PASS.
- `python3 -m unittest discover -s tests -v`: **16/16 PASS** في بيئة المراجعة.
- `python3 scripts/pm_runner.py --dry-run`: PASS؛ لا يستدعي Claude الحقيقي.
- `python3 scripts/check_release.py --root .`: يفشل بشكل متوقع بسبب غياب `release/manifest.json`؛ الصحيح أنه لا يتظاهر بأن التطبيق مكتمل.
- اختبارات المحاكاة استخدمت عميل Claude وهميًا في الحالات: لا تغيير / تغيير ملف بلا إغلاق مهمة / رفض صلاحية / إغلاق مهمة مع ملف / إصدار قديم، وليس استدعاء حساب المستخدم أو جهازه.

## ما لم يختبر

- تشغيل Claude Code أو صلاحياته في جهاز المستخدم.
- نجاح Linux bubblewrap sandbox في الجهاز المستهدف أو دوره مع npm/dotnet ومنافذ SQL Server.
- بناء React + ASP.NET Core وتطبيق EF Migrations.
- وجود كتب 2026/2027 الرسمية أو استخراج دروسها الدقيقة أو التحقق من ترخيصها.
- محتوى ألعاب يعمل، أو مراجعة تربوية مستقلة، أو تجربة الطفل.
- صحة استعادة النسخ الاحتياطية، وE2E، وإشعارات الفشل أو تقارير إدارة ولي الأمر.
- استمرار service بعد إعادة تشغيل جهاز المستخدم.

## المخاطر المتبقية والتوصية

- استمرارية «بلا توقف نهائيًا» غير مضمونة بسبب حدود الخدمة والإنفاق والكتب والإشراف البشري.
- يجب تشغيل الوكيل أول مرة في مستخدم لينكس غير مميز ومجلد عمل جديد لا يتضمن بيانات الطفل، صورًا خاصة، مفاتيح، أو بيانات مؤسسية.
- أوصي ببدء أول دورة اختبارية فقط بعد تثبيت sandbox والتحقق من `claude auth status`، ثم بناء محرك منهج مصغر من كتاب رياضيات فعلي؛ بعدها استكمال الوحدات كلها وفق inventory مستقل؛ لا تعتمد على كمال وهمي من JSON.
- لا تفعّل systemd ولا ترفع سقف الدورات حتى يصبح `--once` آمنًا وفعالًا على جهازك.

**القرار:** V4 أقوى فنيًا من V3 من حيث العقد، والمشغّل، ومحاولات منع الاكتمال الوهمي؛ لكنه **ليس نظام تعليم جاهزًا ولا يضمن استمرارية كاملة**. حالة المنصة الآن: `NOT_STARTED`, والمشغّل: `LOCALLY_TESTED`, والاختبار الميداني: `NOT_TESTED`.
